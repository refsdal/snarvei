# Snarvei: Go backend, embedded SPA, self-hostable image

Date: 2026-09-04
Status: approved design, ready for an implementation plan

## Summary

Snarvei leaves Cloudflare Workers. The backend becomes one static, CGO-free Go
binary that serves the API, the public redirect and the admin SPA from a single
process. The SPA is a Vite + React + Material UI app on TanStack Router, built
ahead of time and compiled into the binary with `go:embed`. The binary ships in
a distroless `static` image published to `ghcr.io/refsdal/snarvei`, built,
signed and released exactly the way Pjokk (`github.com/refsdal/pjokk`) does it.

The product does not change: organizations, teams, links under `/l/{slug}`,
retargetable redirects with history, per-link click analytics, email
invitations, email/password sign-in with optional TOTP. Two features are
dropped because the Go auth library has no equivalent: passkeys, and the
region/city/colo/ASN columns of click analytics (country survives). There is no
data migration; the new deployment starts empty.

## Decisions taken during brainstorming

| Topic | Decision |
| --- | --- |
| Database | Postgres 17 via pgx v5 + sqlc + goose. No SQLite driver. |
| Auth | Limen (`github.com/thecodearcher/limen`) with `credential-password`, `two-factor` and `organization` plugins, confined to one package behind an interface. Passkeys dropped. Teams are Snarvei's own tables. |
| Existing data | Fresh start. Nothing is exported from D1. |
| Hosting | Container behind Cloudflare proxied DNS on a host the repo does not manage. Client IP via `TRUSTED_PROXY_HOPS`; country via `CF-IPCountry`. |
| Frontend | Keep React 19 + MUI 9. Replace react-router with TanStack Router + TanStack Query, and hand-written fetch types with an `openapi-fetch` client generated from the spec. |
| JS toolchain | bun + biome, like Pjokk. pnpm, ESLint and Prettier are removed. |
| Email | SMTP. Absent configuration drops mail with a redacted log line. |
| Profile images | Kept, through a `storage.Storage` port with `fs` and `s3` drivers. |
| API contract | Spec-first: `openapi/snarvei.yaml` drives oapi-codegen (server), kin-openapi (runtime validation) and openapi-typescript (client). |
| Releases | Merging to `main` is releasing: svu computes the version from Conventional Commits, GoReleaser publishes. PRs push preview images. |
| Landing the work | Phased pull requests straight to `main`. The first one removes the Workers deployment. |
| License | AGPL-3.0-only, same file as Pjokk. |

## 2. HTTP surface

Every request enters `web.Handler(api.NewHandler(deps))`. Order of matching:

1. `GET /healthz`: liveness. Constructs nothing, touches nothing. Returns
   `200 {"ok":true,"service":"snarvei","version":"<ldflags version>"}`.
2. `GET /readyz`: readiness. `SELECT 1` on the pool. `200 {"ok":true}` or
   `503 {"ok":false,"error":"..."}`. Both probes send `Cache-Control: no-store`
   and never the SPA security headers. `/api/health` does not exist any more.
3. `GET /l/{slug}`: the redirect. See section 5.
4. `/api/auth/*`: Limen's handler, allowlisted (section 3).
5. `/api/*`: the spec'd API. Unknown `/api/` paths return
   `404 {"code":"NOT_FOUND"}` in the same envelope as every other API error.
6. `GET /openapi.json` (the embedded spec) and `GET /scalar` (embedded loader
   page pointing at `/openapi.json`). Both public, as today.
7. `GET /images/profile/{key}`: streamed from `storage.Storage` with
   `Cache-Control: public, max-age=31536000, immutable` (keys are content-hashed).
8. `GET /robots.txt`: `User-agent: *\nDisallow: /\n`.
9. Everything else: embedded static asset if the path exists, else
   `index.html` (SPA fallback). Hashed assets under `/assets/` get
   `Cache-Control: public, max-age=31536000, immutable`; `index.html` gets
   `no-cache`.

Non-API responses carry today's security header set: `X-Content-Type-Options:
nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`,
`Permissions-Policy: camera=(), microphone=(), geolocation=()`,
`Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy:
same-origin`, and a CSP of `default-src 'self'; script-src 'self'; style-src
'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:;
connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`.
`/scalar` is the one exception: its page loads the Scalar bundle from the
Scalar CDN, so it gets its own CSP that allows that script host, exactly as
Pjokk's `scalar.html` does. `unsafe-inline` for styles is required by Emotion
(MUI). HSTS is the reverse proxy's job.

### API endpoints (all in `openapi/snarvei.yaml`)

Session-gated unless noted. `{orgId}` is always resolved and checked against
the caller's membership by middleware before a handler runs.

Public:

- `GET /api/config` → `{ appName, openSignup }` so the landing page can hide
  sign-up.

Me:

- `GET /api/me` → user (id, name, email, image, twoFactorEnabled) and session
  (id, expiresAt, activeOrganizationId). Never the token.
- `PATCH /api/me` → name.
- `POST /api/me/profile-image` (multipart, ≤ 2 MiB, png/jpeg/webp) and
  `DELETE /api/me/profile-image`.
- `POST /api/me/email` (newEmail, password) sends a confirmation to the new
  address; `POST /api/me/email/confirm` (token) applies it. Snarvei owns this
  flow because Limen has no change-email route. Tokens are random 32 bytes,
  stored as SHA-256 in `email_change_requests`, valid 1 hour, single use.
- `GET /api/me/sessions` → list (id, createdAt, lastAccess, userAgent,
  current). `DELETE /api/me/sessions/{id}` and `DELETE /api/me/sessions`
  (all others). Snarvei owns these so a session's token is never serialised.
- `DELETE /api/me` (password) deletes the account: sessions, accounts,
  memberships and team memberships go with it; links keep their rows with
  `created_by`/`updated_by` set to null. A user who is the last owner of any
  organization gets `409 LAST_OWNER`.

Organizations:

- `GET /api/organizations` → the caller's organizations with their role.
- `POST /api/organizations` (name, slug) → any authenticated user may create.
  The creator becomes `owner`. Slug rules and uniqueness as today.
- `POST /api/organizations/{orgId}/switch` → sets the session's active org.
- `GET /api/organizations/{orgId}/members` → members with roles.
- `GET /api/organizations/{orgId}/invitations`,
  `POST /api/organizations/{orgId}/invitations` (email, role in
  `admin|member`, optional teamId), `DELETE
  /api/organizations/{orgId}/invitations/{id}`. Owner/admin only.
- `GET /api/invitations/{id}` (public: returns org name, inviter name, role,
  team name, expiry and `hasAccount`, never the email; the id is an
  unguessable UUID), `POST /api/invitations/{id}/accept` and
  `POST /api/invitations/{id}/reject` (session required; the session's email
  must match the invitation). Accept adds the org membership through Limen
  and, when the invitation carries a team, the team membership in the same
  transaction.
- `POST /api/invitations/{id}/register` (public; name, password): for an
  invitee whose email has no account. Creates the user through Limen's Go
  API, accepts the invitation and starts a session. Works regardless of
  `OPEN_SIGNUP`; rate-limited (section 3). The invitation id is the
  credential: whoever holds the link can register the account bound to the
  invitee's email (the same trust model as before), so links must not be
  exposed.

Teams:

- `GET /api/organizations/{orgId}/teams` → teams the caller can see (all for
  owner/admin, own teams for member), with member counts.
- `POST /api/organizations/{orgId}/teams` (name) → owner/admin.
- `GET /api/teams/{teamId}/members` → any member of the team, plus
  owner/admin. `POST /api/teams/{teamId}/members` (userId),
  `DELETE /api/teams/{teamId}/members/{userId}` → owner/admin.

Links:

- `GET /api/links?organizationId=&teamId=&page=&pageSize=` → paginated,
  filtered to teams the caller can access.
- `POST /api/links` (organizationId, teamId, targetUrl, redirectStatus,
  title, description, optional slug) → generated slug retries on collision;
  a taken custom slug is `409 SLUG_TAKEN`. Slug rules unchanged
  (`^[a-z0-9]+(?:-[a-z0-9]+)*$`, 3–64, lower-cased, trimmed). Target URL rules
  unchanged (absolute http/https, no credentials, no loopback or private
  hosts).
- `GET /api/links/{id}`, `PATCH /api/links/{id}` (targetUrl, redirectStatus,
  isActive, title, description; never slug), `DELETE /api/links/{id}`.
- `GET /api/links/{id}/history` → target changes newest first.
- `GET /api/links/{id}/analytics?days=` → totals, per-day series, top
  referers, top countries. Same shape as today minus region/city/colo/asn.

Error envelope for every API error: `{"code": "...", "message": "...",
"details"?: {...}}`. Validation failures from kin-openapi are mapped to
`400 VALIDATION_FAILED` with a `details.fields` object.

## 3. Auth, tenancy and abuse protection

### Limen

Pinned versions: `limen v0.2.1`, `adapters/sql v0.2.0`,
`plugins/credential-password v0.2.0`, `plugins/two-factor v0.2.0`,
`plugins/organization v0.1.0`. Every one is version-pinned in `go.mod` and
Dependabot bumps them one at a time.

`internal/auth` is the only importer. It exposes:

```go
type Service interface {
    Handler() http.Handler                        // mounted at /api/auth
    SessionFromRequest(context.Context, *http.Request) (*Session, error)
    CreateOrganization(ctx, userID, name, slug) (*Organization, error)
    ListOrganizations(ctx, userID) ([]OrganizationWithRole, error)
    SetActiveOrganization(ctx, sessionID, orgID) error
    MemberRole(ctx, orgID, userID) (Role, error)          // "", owner, admin, member
    ListMembers(ctx, orgID) ([]Member, error)
    CreateInvitation(ctx, orgID, inviterID, email, role) (*Invitation, error)
    GetInvitation(ctx, id) (*Invitation, error)
    AcceptInvitation(ctx, id, userID) (*Membership, error)
    RejectInvitation(ctx, id, userID) error
    CancelInvitation(ctx, orgID, id) error
    ListInvitations(ctx, orgID) ([]Invitation, error)
    DeleteUser(ctx, userID) error
    VerifyPassword(ctx, userID, password) error
}
```

Nothing else in the module names a Limen type. The instance is built once in
`cmd/snarvei` and handed down through `api.Deps`.

Allowlisted Limen HTTP routes (everything else in `knownRouteIDs` is passed to
`limen.WithHTTPDisabledPaths`, and a test probes the concrete paths):

- core: `me`, `signout`
- credential-password: `signin`, `signup` (only when `OPEN_SIGNUP=1`),
  `passwords-change`, `passwords-request-reset`, `passwords-reset`
- two-factor: the routes at `/two-factor/initiate-setup`, `/finalize-setup`,
  `/disable`, `/verify`, `/backup-codes`, `/totp/uri` (route ids as Limen
  names them; `/otp/send` stays disabled, there is no email OTP)

Disabled on purpose: `list-sessions` and `revoke-sessions` (they serialise
tokens; Snarvei has its own), every organization route (Snarvei's API wraps
the Go API so invitations can carry a team and roles are enforced in one
place), `usernames-check`, `passwords-set`, email verification (off, as today).

Session cookie: `snarvei_session`, HttpOnly, SameSite=Lax, Secure when
`APP_URL` is https. Sessions expire after 7 days and slide on use. Password
reset revokes every session of the user, as today. Password hashing is
Limen's default (argon2id).

Password reset, invitation and change-email emails contain links built from
`APP_URL`: `/reset-password?token=`, `/app/invitations/{id}`,
`/app/settings?emailToken=`. The subjects and bodies are today's templates,
moved to Go `text/template` and `html/template`.

### Roles and teams

Org roles: `owner`, `admin`, `member`, stored by Limen's organization plugin.
Snarvei reads them through `MemberRole`. Rules, implemented in `internal/authz`
as pure functions and unit-tested:

- owner and admin can see and mutate every team and link in the org
- member can see and mutate only links in teams they belong to
- a link mutation checks both the org membership and the team's ownership of
  the link
- only owner/admin create teams, manage team membership, invite, cancel
  invitations
- an owner cannot be demoted or removed by this API (there is no role
  management endpoint in V1, same as today)

Teams and team membership are Snarvei's own tables (section 4). Every sqlc
query on `links`, `link_target_history`, `click_events`, `teams` and
`team_members` takes `organization_id` (directly or through a join on the
link's or team's org) in its WHERE clause.

Sign-up is open by default (`OPEN_SIGNUP=1`) because Snarvei is used by a team
that self-registers today; an operator exposing it publicly sets `0`, after
which accounts exist only by accepting an invitation: `POST
/api/auth/signup/credential` is disabled, and the invitation page uses
`POST /api/invitations/{id}/register` (section 2) instead.

### Client IP, hashing, rate limits

- `TRUSTED_PROXY_HOPS` (default 0). At 0 the peer address is the client. At
  N, the client is the N-th address from the right of `X-Forwarded-For`.
  Cloudflare proxied DNS in front of a direct origin is `1`; Cloudflare plus a
  reverse proxy is `2`. `CF-Connecting-IP` is not read; Cloudflare's
  `X-Forwarded-For` carries the same value.
- Country: `CF-IPCountry` when `TRUSTED_PROXY_HOPS > 0` and the header is a
  two-letter code other than `XX`/`T1`; otherwise null.
- IP hashing: HMAC-SHA256 over the address with key `IP_HASH_PEPPER`, or,
  when that is unset, HMAC-SHA256(`AUTH_SECRET`, "snarvei:ip-hash") as the
  key. The same keyed extractor is passed to Limen for its rate-limit keys and
  for the address it writes into session metadata, so nothing stores a raw IP.
- Rate limits: Limen's own database-backed limiter on `/api/auth/*` with its
  defaults for sign-in, sign-up and two-factor and a base rule of 60 per
  minute. In practice this limiter is in-memory per replica for now: Limen
  v0.2.1's DB store int32-casts pgx's int64, so its Postgres-backed store
  cannot be used as-is (fix upstream, or wrap
  `POST /api/auth/signin/credential` with Snarvei's own Postgres limiter,
  when running more than one `server` replica). Snarvei's `internal/ratelimit`
  on `/l/*` at 100 requests per 60 s per hashed IP, `429` with `Retry-After`,
  counters in the `rate_limit` table (fixed window, upsert, rows older than
  two windows deleted opportunistically on write). `POST
  /api/invitations/{id}/register`, `POST /api/me/email` and `POST /api/links`
  share a 30 per minute per hashed IP rule from the same package.

### Logging

One JSON line per event on stdout: `time`, `level`, `event`, plus fields
(`requestId`, `userId`, `path`, `status`, `durationMs`). Unexpected errors are
logged as `request.error` with the stack and answered with
`500 {"code":"INTERNAL"}`. Never log secrets, tokens or link targets. Event
names kept from today where they exist (`email.not_configured`,
`email.send_failed`, `click.record_failed`, `health.degraded`).

## 4. Data model

Postgres, goose migrations embedded in the binary, applied by the default
dispatch mode under advisory lock `MIGRATION_LOCK_KEY` and by `snarvei
migrate`. Migrations are forward-only and expand/contract by policy.

`00001_init.sql` contains:

Limen-shaped tables copied from Pjokk's `00001_init.sql` and
`00002_limen_align.sql` (already runtime-verified there against Limen's own
schema discovery): `users` (with Snarvei's `name`, `image`), `sessions` (with
`active_organization_id`), `accounts`, `verifications`, `organizations`,
`organization_members`, `organization_member_roles`,
`organization_invitations`, `rate_limits`, and the two-factor plugin's tables.
Pjokk-only columns (`plan`, `role`, `banned`, `ban_reason`, impersonation) are
not carried over.

Snarvei tables (ids are `text` UUIDs generated in Go, timestamps `timestamptz`):

- `teams(id, organization_id → organizations cascade, name, created_at, updated_at)`,
  unique `(organization_id, name)`.
- `team_members(team_id → teams cascade, user_id → users cascade, created_at)`,
  primary key `(team_id, user_id)`.
- `invitation_teams(invitation_id → organization_invitations cascade PK, team_id → teams cascade)`.
- `email_change_requests(id, user_id → users cascade, new_email, token_hash unique, expires_at, created_at)`.
- `links(id, organization_id → organizations cascade, team_id → teams cascade,
  slug unique, target_url, redirect_status smallint CHECK (301,302,307) default 302,
  is_active boolean default true, title, description, created_by → users set null,
  updated_by → users set null, created_at, updated_at)`, indexes on `team_id`,
  `organization_id`.
- `link_target_history(id, link_id → links cascade, old_target_url, new_target_url,
  changed_by → users set null, changed_at)`, index on `link_id`.
- `click_events(id, link_id → links cascade, clicked_at, ip_hash, user_agent,
  referer, country, host, path, query_string, redirect_status_used smallint)`,
  indexes on `link_id`, `clicked_at`, `(link_id, clicked_at)`.
- `rate_limit(key text PK, window_start timestamptz, count int)`.

Deleting a link removes its history and clicks by cascade. Deleting a user
nulls authorship and cascades sessions, accounts, memberships and team
memberships. Click privacy rules are unchanged: keyed IP hash only, `utm_*`
query parameters only, referer reduced to origin + path, user agent capped at
256 characters.

`updated_at` is set by the application, not triggers.

## 5. Redirect and analytics

`GET /l/{slug}` runs outside the session middleware:

1. Rate limit check (section 3).
2. `SELECT` the active link by slug. Miss or inactive: `404 text/plain "Link
   not found"`, `Cache-Control: no-store`.
3. Respond with the link's status and `Location`, `Cache-Control: no-store`.
4. After the response is written, hand a `clickEvent` value to the recorder.

The recorder is a `sync.WaitGroup`-tracked goroutine per click with a 5 s
context, inserting one row; errors log `click.record_failed` with link id and
slug. On SIGTERM the server stops accepting, drains in-flight requests (20 s),
then waits for the recorder (5 s). A click can be lost on a hard kill; that
matches today's `waitUntil` guarantee.

Analytics queries are sqlc SQL: totals, per-day counts over the requested
window (`days` in 1..365, default 30), top 10 referers, top 10 countries.

## 6. Frontend

`apps/frontend` keeps React 19, MUI 9 (+ icons, X Data Grid), Emotion,
`react-qr-code`, zod. It gains `@tanstack/react-router`, `@tanstack/react-query`,
`openapi-fetch`, `limen-auth`. `react-router-dom` is removed.

Routing (`src/router.tsx`, code-based, one root route, lazy components for
every screen except the landing page):

| Path | Screen | Guard |
| --- | --- | --- |
| `/` | landing: sign in, sign up (hidden when the server reports `openSignup=false`), forgot password, two-factor step | redirect to `/app` when signed in |
| `/reset-password` | reset with `token` search param | public |
| `/app` | organization picker | session |
| `/app/invitations/{id}` | invitation accept/reject, or register when signed out and the server reports the email has no account | public |
| `/app/settings` | profile, email (with `emailToken` confirm), password, two-factor, sessions | session |
| `/app/{org}/dashboard` | dashboard | session + org |
| `/app/{org}/links` | links table | session + org |
| `/app/{org}/links/{linkId}` | details, history, analytics | session + org |
| `/app/{org}/organization` | members, teams, invitations | session + org |

`{org}` is the organization slug (today's `buildOrganizationPath` behaviour).
Guards are TanStack `beforeLoad` hooks over a `session` query; the org layout
route resolves the slug against the organizations query and switches the
active organization server-side when it differs.

Data: every server call is a TanStack Query with keys `['me']`,
`['organizations']`, `['teams', orgId]`, `['links', orgId, filters]`,
`['link', id]`, `['history', id]`, `['analytics', id, days]`,
`['invitations', orgId]`, `['members', orgId]`, `['sessions']`. Mutations
invalidate the affected keys. No persistence layer, no PWA (unchanged from
today).

`GET /api/config` (public, unauthenticated) returns `{ appName, openSignup }`
so the landing page can hide sign-up; it is part of the spec.

Auth client: `limen-auth/react` with the two-factor plugin for sign-in,
sign-up, sign-out, session, two-factor setup/verify/disable/backup codes and
password change/reset. `openapi-fetch` for everything under `/api/*` that is
not `/api/auth`.

Removed UI: passkeys section. Everything else on the settings page and the
organization page carries over with the same MUI components.

Dev loop: `bun run dev` starts Vite on 5173 proxying `/api`, `/l`, `/healthz`,
`/readyz`, `/openapi.json`, `/scalar`, `/images` to `bun run dev:server` on
3000, which runs against `docker-compose.test.yml`'s Postgres (or any
`DATABASE_URL`).

## 7. Build, image, release

Copied from Pjokk with names swapped and the landing-site pieces removed.

- `scripts/build-artifacts.sh`: `bun run build` (Vite writes
  `dist/client`), overlay into `apps/server/internal/web/dist`, then
  `CGO_ENABLED=0 GOOS=linux GOARCH={amd64,arm64} go build -trimpath
  -ldflags "-s -w -X main.version=$(git describe --tags --always --dirty)"`
  into `dist/server/linux/<arch>/snarvei`; restore the overlay on exit.
- `Dockerfile`: `FROM gcr.io/distroless/static-debian12:nonroot@sha256:...`
  (digest pinned, Dependabot bumps it), `ARG TARGETPLATFORM`, `ARG
  BINARY_ROOT=dist/server`, `COPY --chown=nonroot:nonroot docker/data-skel/
  /data/`, `COPY ${BINARY_ROOT}/${TARGETPLATFORM}/snarvei /app/snarvei`,
  `ENV PORT=3000`, `EXPOSE 3000`, `HEALTHCHECK CMD ["/app/snarvei",
  "healthcheck"]`, `ENTRYPOINT ["/app/snarvei"]`. Nothing compiles inside
  Docker. `import _ "time/tzdata"` in `main.go`.
- Dispatch (`argv[1]`): none → migrate under advisory lock, then serve;
  `server` → serve only; `migrate` (alias `migrations`) → apply and exit;
  `healthcheck` → GET `/healthz` on `PORT`, exit 0/1; anything else → usage,
  exit 2. No `worker`, `cron` or `landing` modes: Snarvei has no scheduled
  work and no separate marketing site.
- `.goreleaser.yaml`: `dist: dist/goreleaser`, before hook
  `scripts/spa-embed-overlay.sh`, one build (`apps/server`, `./cmd/snarvei`,
  linux amd64/arm64, `-trimpath`, `-s -w -X main.version={{.Version}}`),
  tar.gz archives named `snarvei_{{.Version}}_{{.Os}}_{{.Arch}}`,
  `checksums.txt`, syft SBOMs, keyless cosign `sign-blob --bundle` on the
  checksum file, `dockers_v2` for `ghcr.io/refsdal/snarvei` with tags
  `{{.Version}}`, `{{.Major}}.{{.Minor}}`, `{{.Major}}`, `latest`,
  `sha-{{.FullCommit}}`, `build_args BINARY_ROOT: "."`, `extra_files:
  docker/data-skel`, cosign on every image, Conventional-Commits changelog
  groups, release footer naming the image. Snapshot template
  `{{ incpatch .Version }}-snapshot.{{ .ShortCommit }}`.
- `.github/workflows/test.yml` (`workflow_call`): Postgres 17 service,
  `jdx/mise-action` installing `go bun aqua:goreleaser/goreleaser`, Go module
  cache, `bun install --frozen-lockfile`, `bun run check`, `goreleaser check`,
  `bun run test`, `go vet ./...`, `go test -p 1 -count=1 ./...` with
  `TEST_DATABASE_URL`.
- `.github/workflows/ci.yml` (`pull_request`): `test.yml`, then an `image`
  job that runs `scripts/build-artifacts.sh`, builds the amd64 image, smoke
  tests it against a Postgres container (`/healthz`, `/readyz`, a sign-up, a
  link creation, a redirect), runs the Playwright suite against it via
  `scripts/e2e-stack.sh`, and pushes it to ghcr.io as the semver prerelease
  `<svu next>-pr.<number>`. Concurrency cancels superseded runs.
- `.github/workflows/release.yml` (`push: main`, `workflow_dispatch` with
  `dry_run` and `allow_major`): `test.yml`, then svu computes the next
  version from commits since the last `v*` tag; when there is nothing
  releasable the job ends green; otherwise it tags, runs `goreleaser
  release`, and deletes the tag if publishing fails. `id-token: write` for
  cosign, `packages: write`, `contents: write`.
- The pipeline does not roll anything out. Deployment is the operator's:
  run `snarvei migrate` (or rely on the default mode), then point the
  deployment at the new tag.

Version reporting: `main.version` from ldflags, `dev` when unset; shown by
`/healthz` and in the boot log.

## 8. Configuration

Read once at startup by `internal/config`, which collects every error and
prints them all before exiting 1. `.env.example` lists every variable.

Required:

| Variable | Rule |
| --- | --- |
| `DATABASE_URL` | libpq URL |
| `APP_URL` | absolute http(s) origin; `https` makes cookies `Secure` |
| `AUTH_SECRET` | ≥ 32 bytes |
| `STORAGE_DRIVER` | `fs` or `s3` |
| `STORAGE_FS_PATH` | required when `fs` |
| `S3_BUCKET`, `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | required when `s3`; `S3_REGION` optional, default `auto` |

Optional:

| Variable | Default | Effect |
| --- | --- | --- |
| `PORT` | `3000` | listen port |
| `APP_NAME` | `Snarvei` | display name, TOTP issuer, email sender name |
| `TRUSTED_PROXY_HOPS` | `0` | see section 3 |
| `OPEN_SIGNUP` | `1` | `0` closes self-registration |
| `IP_HASH_PEPPER` | derived from `AUTH_SECRET` | keeps analytics stable across secret rotation |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `EMAIL_FROM` | unset | all five or none; STARTTLS on 587, implicit TLS on 465, plain only for loopback hosts |
| `MIGRATION_LOCK_KEY` | `1935762089` | advisory lock id for startup migration |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `E2E_TEST_HOOKS` | `0` | `1` enables `GET /api/_test/mail` (last invitation ids and reset tokens) for the Playwright suite; refused unless `APP_URL` is a loopback origin |

The boot log names every optional subsystem that is off (email, s3).

`docker-compose.selfhost.yml`: Postgres 17 with a `db-data` volume and the
published image in default mode, `STORAGE_DRIVER=fs`, `STORAGE_FS_PATH=/data`
on a `snarvei-data` volume, `AUTH_SECRET` required from the environment,
`APP_URL` default `http://localhost:3000`, `SNARVEI_TAG` default `latest`.
`docker-compose.yml` is the same stack built from `dist/server` for
contributors. `docker-compose.test.yml` is Postgres only on 55432.

## 11. Implementation phases

Each phase is one pull request to `main`, reviewed and green on `ci.yml`.

1. Foundation. Delete the Workers deployment (workflows, wrangler, worker
   sources, Drizzle, Vitest). Add `LICENSE`. Move the SPA to `apps/frontend`
   on bun + biome, still on react-router, building to `dist/client`.
   Scaffold `apps/server`: config, db pool, goose with `00001_init.sql`,
   `web` embed with placeholder, `/healthz`, `/readyz`, dispatch, graceful
   shutdown, testrig. `openapi/snarvei.yaml` with only `/healthz`,
   `/readyz`, `/api/config` and codegen wired. Dockerfile, `.dockerignore`,
   data-skel, build scripts, compose files, `.mise.toml`, `.env.example`,
   `test.yml`, `ci.yml` (without e2e yet). After this PR the image boots,
   migrates and serves the old SPA.
2. Auth and tenancy. `internal/auth` on Limen with the allowlist,
   `/api/me` family including sessions, email change, deletion,
   organizations, teams, invitations, `internal/email` SMTP, `storage` with
   profile images, `authz`, all matching Go tests.
3. Links. Links CRUD, history, analytics, custom slugs, redirect with the
   recorder, rate limiting, Scalar and `/openapi.json`.
4. Frontend port. TanStack Router and Query, generated client, `limen-auth`,
   every screen ported, passkeys removed, sign-up hidden when closed,
   invitation registration flow.
5. Release. Playwright suite in `e2e/`, `e2e-stack.sh`, e2e in `ci.yml`,
   `.goreleaser.yaml`, `release.yml`, Dependabot, docs rewrite. The first
   merge of this PR to `main` produces `v0.1.0`.

Phases 2 and 3 can be developed in parallel branches once phase 1 has merged;
phase 4 needs both.
